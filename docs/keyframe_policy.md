# 关键帧策略与编号

本策略用于 SLAMIBOT 经 ROS 适配器发送到 FieldMind 的语义关键帧。框架的 `/keyframe` 拼图预览话题独立运行。

## 保存条件

以同一采集会话、坐标会话和相机的最近一张**已持久化接受**的关键帧为基准；跳过的帧、HTTP 失败和过载拒绝都不会推进该基准。首帧立即保存。

| 条件 | 行为 |
|---|---|
| 距上一关键帧不足 0.5 秒 | 跳过，即使正在快速运动 |
| 平移 ≥0.5 米或三维旋转 ≥15° | 保存 |
| 间隔 ≥3 秒，且平移 ≥0.05 米或三维旋转 ≥2° | 保存，补充慢速运动覆盖 |
| 有可比较位姿，但运动小于 0.05 米且小于 2° | 不保存，超时也不例外 |
| 没有可比较位姿，且间隔 ≥3 秒 | 按时间保存，明确标记 `pose_unavailable` |
| 源时间回退 | 跳过并标记 `time_rollback`，由 ROS 适配器切换坐标会话 |

平移使用三维欧氏距离，旋转使用归一化四元数夹角，四元数正负等价。所有运动量都相对已接受的关键帧累计，避免逐帧移动很小导致永远不保存。5 厘米／2° 是默认抖动容差，需要根据实机 SLAM 噪声调整；超过容差的定位漂移仍可能触发采样。

优先比较两帧相机位姿；不可比较时，使用两帧在同一坐标系中的机身位姿。不会混减机身和相机位姿，也不会因此填充 `camera_pose`。使用机身位姿可在尚未标定相机外参时抑制静止重复帧，空间查询仍只使用实际存在的相机位姿。

完全没有位姿时无法判断静止，因此保留时间采样，适用于离线图像回放和纯相机测试。要在设备静止时停止历史增长，须接入有效 SLAM 机身位姿或相机位姿。

## 参数与诊断

```bash
slamibot-fieldmind \
  --distance-m 0.5 --rotation-deg 15 \
  --max-interval-s 3 --min-interval-s 0.5 \
  --timeout-distance-m 0.05 --timeout-rotation-deg 2
```

参数须为正数，超时运动门槛不大于对应的主门槛。`--max-interval-s` 表示满足运动条件后的超时补帧门槛，静止时不保证每 3 秒保存。

接收响应和保存元数据的 `selection` 包含触发原因、距离、角度、时间间隔、选帧位姿来源和判断状态。状态包括 `first`、`selected`、`stationary`、`waiting_for_threshold`、`min_interval`、`pose_unavailable`、`time_rollback`。健康接口及 MCP `index_status` 返回 `keyframe_policy`，计数 `stationary_skipped` 表示主动静止跳过，`time_only_accepted` 表示无法比较位姿时接受的时间采样（不含首帧）。主动静止跳过不计为 `overdue_gaps`；容量或磁盘拒绝后的超时恢复才计入该指标。

## 编号与重试

新记录示例：

```text
kf-93b922c324faa6b2d04cf1e95ba96a35-20261025T010807123Z
images/kf-93/kf-93b922c324faa6b2d04cf1e95ba96a35-20261025T010807123Z.jpg
```

32 位十六进制唯一标识由采集会话、坐标会话、设备、相机、驱动启动标识和原始序号计算，不使用会随重试变化的接收时间，也不采用跨设备易冲突的连续整数。后缀为 UTC 毫秒时间，优先 `captured_at`，未提供时为首次接受观测的 `received_at`。它不是精确曝光同步证明，须结合 `timestamp_source`、`sync_quality`、原始 ROS 时间和设备时间解释。

独立的 `observation_key` 数据库唯一索引负责幂等，同一源帧即使重试接收时间变化，也返回首次持久化的完整 ID 和图片路径。新 ID 同时用于 SQLite、JPEG 名、向量行引用和 MCP `frame_id`，Agent 将其作为不透明标识使用。

观测表 schema 1 自动事务迁移至 2，补充去重字段及唯一索引，历史帧 ID、图片路径和 embedding 保持原样。旧编号仍可通过 `get_frame`、`get_frame_image` 查询；迁移不重算模型向量。旧版本后端不支持 schema 2，回退前应从备份恢复数据库。

## 容量与验证边界

静止过滤减少重复 JPEG、向量、数据库记录及 RADIO 推理。它不等于已经排除其他内存泄漏。接收写队列上限 64、文字任务上限 8、当前图像缓存最多 8 路、内存预取最多 4 条、磁盘 pending 最多 32 条，JPEG 不在内存中累计。历史检索仍会按查询范围加载元数据及向量，大范围搜索的内存随候选数量增长；长时间运行的内存峰值仍需实机测量。

自动化验证包含静止、抖动、慢速运动、阈值边界、原地旋转、时间回退、机身位姿回退、持续刷新当前画面、重试与重启幂等、旧数据库迁移及图片／向量恢复。测试使用可控位姿与轻量编码器，不替代真实 SLAM 静止噪声和 NX 长时间内存测试。

2026-10-25 本机验证：非慢测回归 248 项通过，最终计数项补充后再次运行后端定向测试 24 项通过；框架 Compose 与文档的 pre-commit 检查通过。连续 120 次、覆盖十分钟的模拟静止／抖动输入只保存首张历史图片，实时缓存更新至最后一帧。
